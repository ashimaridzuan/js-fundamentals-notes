LESSON 2

Data Types & Variables

Every piece of data in JavaScript has a type. Understanding types is the foundation of everything else.

1Declaring Variables
javascript
// const — value never changes (use by default)
const name = 'Alice';

// let — value can change
let score = 0;
score = 10; // OK

// var — avoid! has scoping bugs
var age = 25;

console.log(name);  // 'Alice'
console.log(score); // 10
💡 Tip: Default to const. Use let when value changes. Never use var.
2Primitive Types
javascript
// String
const greeting = 'Hello, World!';
const msg = `Hi, ${greeting}`; // template literal

// Number (integers AND decimals — one type)
const age = 25;
const price = 9.99;

// Boolean
const isLoggedIn = true;

// Null & Undefined
let x;        // undefined — not yet assigned
let y = null; // null — intentionally empty

console.log(typeof 42);        // 'number'
console.log(typeof 'hello');   // 'string'
console.log(typeof true);      // 'boolean'
console.log(typeof undefined); // 'undefined'
console.log(typeof null);      // 'object' ← known JS quirk!
3Operators
javascript
// Arithmetic
console.log(5 + 3);  // 8
console.log(10 % 3); // 1 — remainder
console.log(2 ** 3); // 8 — exponent

// Comparison (always use === not ==)
console.log(5 === 5);   // true  — strict: value AND type
console.log(5 === '5'); // false — different types
console.log(5 == '5');  // true  — loose: AVOID this!

// Logical
console.log(true && false); // false — AND
console.log(true || false); // true  — OR
console.log(!true);         // false — NOT
⚠️ Always use ===. Double equals == converts types silently and causes bugs.
LESSON 3

Conditionals

Let your program make decisions based on whether something is true or false.

1if / else if / else
javascript
const score = 75;

if (score >= 90) {
  console.log('A');
} else if (score >= 80) {
  console.log('B');
} else if (score >= 70) {
  console.log('C'); // ← this runs
} else {
  console.log('Fail');
}
2Ternary & switch
javascript
// Ternary — shorthand if/else
const age = 20;
const status = age >= 18 ? 'adult' : 'minor';
console.log(status); // 'adult'

// switch — check one variable against many values
const day = 'Monday';
switch (day) {
  case 'Monday': console.log('Start of week'); break;
  case 'Friday': console.log('Almost weekend!'); break;
  case 'Saturday':
  case 'Sunday':  console.log('Weekend!'); break;
  default:        console.log('Midweek');
}
3Truthy & Falsy
javascript
// Falsy: false, 0, '', null, undefined, NaN
// Truthy: everything else

const username = '';
if (username) {
  console.log('Welcome!');
} else {
  console.log('Please enter a username'); // runs
}

console.log(Boolean(0));       // false
console.log(Boolean(''));      // false
console.log(Boolean([]));      // true — empty array is truthy!
console.log(Boolean('false')); // true — non-empty string is truthy!
LESSON 4

Loops

Repeat code without writing it over and over. Essential for working with collections.

1for & while
javascript
// for — when you know the count
for (let i = 0; i < 5; i++) {
  console.log(i); // 0 1 2 3 4
}

// while — when you don't know the count
let count = 0;
while (count < 3) {
  console.log(count);
  count++;
}
2for...of & for...in
javascript
// for...of — cleanest way to loop an array
const fruits = ['apple', 'banana', 'mango'];
for (const fruit of fruits) {
  console.log(fruit);
}

// for...in — loops over object keys
const person = { name: 'Alice', age: 25 };
for (const key in person) {
  console.log(key + ': ' + person[key]);
}

// break & continue
for (let i = 0; i < 5; i++) {
  if (i === 2) continue; // skip 2
  if (i === 4) break;    // stop at 4
  console.log(i); // 0 1 3
}
LESSON 5

Functions

Reusable blocks of code — the most important concept in JavaScript.

1Three ways to write functions
javascript
// 1. Declaration (hoisted — can call before definition)
function greet(name) {
  return 'Hello, ' + name + '!';
}

// 2. Expression
const greet2 = function(name) {
  return 'Hello, ' + name + '!';
};

// 3. Arrow (ES6+) — most common in modern code
const greet3 = (name) => 'Hello, ' + name + '!';
const double = n => n * 2;          // single param, no parens needed
const sayHi = () => 'Hi!';          // no params

console.log(greet('Alice'));  // 'Hello, Alice!'
console.log(double(5));       // 10
2Default params & Higher-Order Functions
javascript
// Default parameters
function greet(name = 'stranger') {
  return `Hello, ${name}!`;
}
console.log(greet());        // 'Hello, stranger!'
console.log(greet('Alice')); // 'Hello, Alice!'

// Higher-order: functions that take or return functions
function runTwice(fn) { fn(); fn(); }
runTwice(() => console.log('Hello!')); // Hello! Hello!

function multiplier(factor) {
  return n => n * factor;
}
const triple = multiplier(3);
console.log(triple(5)); // 15
LESSON 6

Arrays

Ordered lists of values. The backbone of data manipulation in JavaScript.

1Creating & Modifying
javascript
const fruits = ['apple', 'banana', 'mango'];
console.log(fruits[0]);     // 'apple'
console.log(fruits.length); // 3

fruits.push('grape');    // add to end
fruits.pop();            // remove from end
fruits.unshift('kiwi'); // add to start
fruits.shift();          // remove from start
console.log(fruits);
2map / filter / reduce
javascript
const nums = [1, 2, 3, 4, 5];

const doubled = nums.map(n => n * 2);
console.log(doubled); // [2,4,6,8,10]

const evens = nums.filter(n => n % 2 === 0);
console.log(evens); // [2,4]

const sum = nums.reduce((total, n) => total + n, 0);
console.log(sum); // 15

// Chain them!
const result = nums.filter(n => n > 2).map(n => n * 10);
console.log(result); // [30,40,50]
3Searching & other methods
javascript
const fruits = ['apple', 'banana', 'mango'];

console.log(fruits.includes('banana'));            // true
console.log(fruits.find(f => f.startsWith('b'))); // 'banana'
console.log(fruits.some(f => f.length > 5));      // true
console.log(fruits.every(f => f.length > 3));     // true

const a = [1,2,3], b = [4,5,6];
console.log([...a, ...b]);    // [1,2,3,4,5,6]
console.log(a.join(' - '));   // '1 - 2 - 3'
console.log(a.slice(1, 3));   // [2,3] — non-destructive
LESSON 7

Objects

Key-value pairs to model real-world data. One of the most important structures in JavaScript.

1Creating, accessing, modifying
javascript
const person = { name: 'Alice', age: 25, city: 'London' };

console.log(person.name);    // dot notation
console.log(person['city']); // bracket notation

person.age = 26;        // update
person.email = 'a@b.c'; // add
delete person.city;     // remove
console.log(person);
2Methods, destructuring, spread
javascript
// Methods — functions inside objects
const person = {
  name: 'Alice',
  greet() { return 'Hi, I am ' + this.name; }
};
console.log(person.greet()); // 'Hi, I am Alice'

// Destructuring
const { name, greet } = person;
console.log(name); // 'Alice'

// Spread — merge objects
const defaults = { theme: 'light', lang: 'en' };
const custom   = { theme: 'dark' };
const config   = { ...defaults, ...custom };
console.log(config); // { theme: 'dark', lang: 'en' }
3Object methods & arrays of objects
javascript
const scores = { Alice: 90, Bob: 75, Carol: 88 };
console.log(Object.keys(scores));    // ['Alice','Bob','Carol']
console.log(Object.values(scores));  // [90,75,88]
for (const [name, score] of Object.entries(scores)) {
  console.log(`${name}: ${score}`);
}

// Arrays of objects — most common real-world pattern
const users = [
  { id: 1, name: 'Alice', age: 25 },
  { id: 2, name: 'Bob',   age: 17 },
];
const adults = users.filter(u => u.age >= 18);
console.log(adults.map(u => u.name)); // ['Alice']
4Objects vs Primitives — Copy vs Reference
javascript
// Primitives store a COPY
let a = 42;
let b = a;
b = 99;
console.log(a); // 42 — unchanged

// Objects store a REFERENCE (pointer to same object)
const obj = { data: 42 };
const ref = obj;
ref.data = 99;
console.log(obj.data); // 99 — changed! same object

// Reassigning a variable breaks the reference
let animal = { species: 'dog' };
let dog = animal;
animal = { species: 'cat' }; // new object
console.log(dog.species); // 'dog' — still points to old one
💡 Primitive = photocopy. Object = shared Google Doc link.

Scope & Closures

Understanding where variables live and how functions remember their environment.

1Block scope — let & const vs var
javascript
// let/const are block-scoped — stay inside {}
{
  let blockLet = 'inside';
  const blockConst = 'also inside';
  console.log(blockLet); // works
}
// console.log(blockLet); // ReferenceError!

// var leaks out of blocks (this is why we avoid it)
{
  var leaked = 'oops';
}
console.log(leaked); // 'oops' — bad!

// let in loops — each iteration has its own i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// prints: 0, 1, 2 (correct with let)
// with var it would print: 3, 3, 3 (wrong!)
2Function scope & closures
javascript
// Closure: inner function remembers outer variables
function makeCounter() {
  let count = 0; // private to makeCounter
  return function() {
    count++;
    return count;
  };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
// count is not accessible outside — it's private!
3Practical closure patterns
javascript
// Factory function — each call gets its own scope
function createMultiplier(factor) {
  return n => n * factor; // 'factor' is remembered
}
const double = createMultiplier(2);
const triple = createMultiplier(3);
console.log(double(5)); // 10
console.log(triple(5)); // 15

// Memoization — cache expensive results
function memoize(fn) {
  const cache = {};
  return function(n) {
    if (cache[n] !== undefined) return cache[n];
    cache[n] = fn(n);
    return cache[n];
  };
}
const slowSquare = memoize(n => n * n);
console.log(slowSquare(4)); // 16 (computed)
console.log(slowSquare(4)); // 16 (from cache)

Error Handling

Write code that fails gracefully — catch problems and recover instead of crashing.

1try / catch / finally
javascript
try {
  const result = JSON.parse('invalid json');
} catch (error) {
  console.log('Caught:', error.message);
} finally {
  console.log('This always runs — great for cleanup');
}

// Error types
try {
  null.property;          // TypeError
} catch (e) {
  console.log(e instanceof TypeError); // true
  console.log(e.name);    // 'TypeError'
  console.log(e.message); // Cannot read properties of null
}
2Throwing custom errors
javascript
function divide(a, b) {
  if (typeof a !== 'number' || typeof b !== 'number') {
    throw new TypeError('Arguments must be numbers');
  }
  if (b === 0) {
    throw new Error('Cannot divide by zero');
  }
  return a / b;
}

try {
  console.log(divide(10, 2)); // 5
  console.log(divide(10, 0)); // throws
} catch (e) {
  console.log(e.message); // 'Cannot divide by zero'
}
3Error handling patterns
javascript
// Safe JSON parse — return null on failure
function safeJSON(str) {
  try {
    return JSON.parse(str);
  } catch {
    return null;
  }
}
console.log(safeJSON('{"a":1}')); // { a: 1 }
console.log(safeJSON('bad'));     // null

// Custom error class
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = 'ValidationError';
    this.field = field;
  }
}

try {
  throw new ValidationError('email', 'Invalid email format');
} catch (e) {
  if (e instanceof ValidationError) {
    console.log(`Field: ${e.field}, Error: ${e.message}`);
  }
}

DOM Events

Respond to user interactions — clicks, typing, form submission, keyboard, and more.

ℹ️ Note: DOM code runs in a browser page. These examples need real HTML elements to work — paste them into your own HTML file or browser console.
1Selecting elements & addEventListener
javascript
// Selecting elements
const btn   = document.querySelector('#myButton');   // first match
const items = document.querySelectorAll('.item');     // all matches

// addEventListener(event, handler)
btn.addEventListener('click', function(event) {
  console.log('Clicked!');
  console.log(event.target); // the element clicked
});

// Arrow function version
btn.addEventListener('click', (e) => {
  e.preventDefault(); // stop default behavior (e.g. form submit, link navigate)
  e.stopPropagation(); // stop event bubbling up to parent
});
2Common events
javascript
const input = document.querySelector('input');
const form  = document.querySelector('form');

// Input events
input.addEventListener('input',  (e) => console.log(e.target.value)); // on every keystroke
input.addEventListener('change', (e) => console.log('Changed'));       // on blur
input.addEventListener('focus',  () => console.log('Focused'));
input.addEventListener('blur',   () => console.log('Lost focus'));

// Form submit
form.addEventListener('submit', (e) => {
  e.preventDefault(); // stop page reload
  const data = new FormData(e.target);
  console.log(data.get('username'));
});

// Keyboard
document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') console.log('Escape pressed');
  if (e.ctrlKey && e.key === 's') {
    e.preventDefault();
    console.log('Ctrl+S pressed');
  }
});
3Event delegation

Add ONE listener to a parent instead of many listeners to each child — more efficient and works for dynamically added elements.

javascript
// Instead of this (bad — listeners on every button):
document.querySelectorAll('.delete-btn').forEach(btn => {
  btn.addEventListener('click', handleDelete);
});

// Do this — one listener on the parent:
document.querySelector('#list').addEventListener('click', (e) => {
  if (e.target.matches('.delete-btn')) {
    e.target.closest('li').remove();
  }
  if (e.target.matches('.edit-btn')) {
    const id = e.target.dataset.id; // read data-id attribute
    openEditor(id);
  }
});
💡 Event delegation works because events "bubble up" from child to parent by default.

Modules

Split code into separate files. Import only what you need. Organize your codebase.

ℹ️ Note: Modules require a build tool (Vite, Webpack) or type="module" on a server. These examples are for reference.
1Named exports & imports
javascript
// math.js — named exports
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export function multiply(a, b) { return a * b; }

// app.js — import only what you need
import { add, PI } from './math.js';
console.log(add(2, 3)); // 5
console.log(PI);        // 3.14159

// Import everything as a namespace
import * as math from './math.js';
console.log(math.multiply(3, 4)); // 12
2Default exports
javascript
// greet.js — one default export per file
export default function greet(name) {
  return `Hello, ${name}!`;
}

// app.js — any name works for default import
import sayHello from './greet.js';
console.log(sayHello('Alice')); // 'Hello, Alice!'

// Mix default and named
// utils.js
export default class Logger { log(msg) { console.log(msg); } }
export const VERSION = '1.0.0';

// import both
import Logger, { VERSION } from './utils.js';
3Re-exports & barrel files
javascript
// index.js — barrel file, re-exports everything
export { add, multiply } from './math.js';
export { greet }         from './greet.js';
export { formatDate }    from './date.js';

// Now consumers import from one place:
import { add, greet, formatDate } from './utils/index.js';

// Dynamic import — load only when needed (code splitting)
async function loadHeavyModule() {
  const { heavyFunction } = await import('./heavy.js');
  heavyFunction();
}
JS ADVANCED

Promises

Handle asynchronous operations — like API calls — without blocking the rest of your code.

1What is a Promise?
javascript
// A Promise is an object representing a future value
// States: pending → fulfilled (resolved) OR rejected

const promise = new Promise((resolve, reject) => {
  const success = true;
  if (success) {
    resolve('Data loaded!');
  } else {
    reject(new Error('Failed'));
  }
});

promise
  .then(data  => console.log('Success:', data))
  .catch(err  => console.error('Error:', err.message))
  .finally(() => console.log('Done — always runs'));
2Promise.all & Promise.allSettled
javascript
const p1 = Promise.resolve('Users data');
const p2 = Promise.resolve('Posts data');
const p3 = Promise.reject(new Error('Config failed'));

// Promise.all — fails fast if ANY rejects
Promise.all([p1, p2])
  .then(([users, posts]) => console.log(users, posts));

// Promise.allSettled — waits for all, never fails
Promise.allSettled([p1, p2, p3]).then(results => {
  results.forEach(r => {
    if (r.status === 'fulfilled') console.log('OK:', r.value);
    if (r.status === 'rejected')  console.log('FAIL:', r.reason.message);
  });
});

Async / Await

Write asynchronous code that reads like synchronous code. Built on top of Promises.

1async & await basics
javascript
// async function always returns a Promise
async function getData() {
  return 'hello'; // same as Promise.resolve('hello')
}
getData().then(v => console.log(v)); // 'hello'

// await pauses until the Promise resolves
async function example() {
  const result = await Promise.resolve(42);
  console.log(result); // 42
  return result;
}
example();
2Fetching data (real-world pattern)
javascript
async function fetchUser(id) {
  try {
    const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const user = await res.json();
    console.log(user.name, user.email);
    return user;
  } catch (err) {
    console.error('Failed to fetch user:', err.message);
    return null;
  }
}

fetchUser(1);
3Parallel requests
javascript
// Sequential — slow (waits for each one)
async function sequential() {
  const user  = await fetch('/api/user').then(r => r.json());
  const posts = await fetch('/api/posts').then(r => r.json());
  // total time = user + posts
}

// Parallel — fast (runs at the same time)
async function parallel() {
  const [user, posts] = await Promise.all([
    fetch('https://jsonplaceholder.typicode.com/users/1').then(r => r.json()),
    fetch('https://jsonplaceholder.typicode.com/posts?userId=1').then(r => r.json()),
  ]);
  console.log(user.name);
  console.log('Posts count:', posts.length);
}

parallel();
💡 Rule: If requests don't depend on each other, run them with Promise.all — never await sequentially when you can parallelize.

OOP & Classes

Object-Oriented Programming lets you model real-world things as objects with data (properties) and behaviour (methods). ES6 class syntax makes it clean and readable.

1Defining a class
javascript
class Animal {
  // constructor runs when you do: new Animal(...)
  constructor(name, sound) {
    this.name  = name;   // 'this' = the new object being created
    this.sound = sound;
  }

  // method — shared by all instances
  speak() {
    console.log(`${this.name} says ${this.sound}!`);
  }
}

const cat = new Animal('Cat', 'Meow');
const dog = new Animal('Dog', 'Woof');
cat.speak(); // Cat says Meow!
dog.speak(); // Dog says Woof!
console.log(cat.name); // Cat
2Inheritance — extends & super
javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    console.log(`${this.name} makes a sound.`);
  }
}

class Dog extends Animal { // Dog inherits from Animal
  constructor(name, breed) {
    super(name);           // call Animal's constructor first!
    this.breed = breed;
  }
  speak() {               // override parent method
    console.log(`${this.name} barks!`);
  }
  info() {
    console.log(`${this.name} is a ${this.breed}`);
  }
}

const d = new Dog('Rex', 'Labrador');
d.speak(); // Rex barks!
d.info();  // Rex is a Labrador
3Getters, Setters & static methods
javascript
class Circle {
  constructor(radius) {
    this._radius = radius; // _ = convention for "private-ish"
  }

  get radius() { return this._radius; }

  set radius(value) {
    if (value < 0) throw new Error('Radius cannot be negative');
    this._radius = value;
  }

  get area() {
    return Math.PI * this._radius ** 2;
  }

  static unitCircle() {  // static = called on the class, not an instance
    return new Circle(1);
  }
}

const c = new Circle(5);
console.log(c.radius);         // 5
console.log(c.area.toFixed(2)); // 78.54
c.radius = 10;
console.log(c.area.toFixed(2)); // 314.16

const unit = Circle.unitCircle();
console.log(unit.radius); // 1
4Practical example — BankAccount
javascript
class BankAccount {
  #balance = 0; // private field (truly private, no _ needed)

  constructor(owner, initialDeposit = 0) {
    this.owner = owner;
    this.#balance = initialDeposit;
  }

  deposit(amount) {
    if (amount <= 0) throw new Error('Deposit must be positive');
    this.#balance += amount;
    console.log(`Deposited $${amount}. New balance: $${this.#balance}`);
  }

  withdraw(amount) {
    if (amount > this.#balance) throw new Error('Insufficient funds');
    this.#balance -= amount;
    console.log(`Withdrew $${amount}. New balance: $${this.#balance}`);
  }

  get balance() { return this.#balance; }
}

const acc = new BankAccount('Alice', 100);
acc.deposit(50);   // Deposited $50. New balance: $150
acc.withdraw(30);  // Withdrew $30. New balance: $120
console.log(acc.balance); // 120
💡 Key OOP ideas: Encapsulation — hide internal data with private fields. Inheritance — child classes reuse parent code. Polymorphism — child classes override parent methods.
JS ADVANCED

JSON

JSON (JavaScript Object Notation) is the universal format for exchanging data — between your JS app and a server, or stored in a file. It looks just like JS objects, with a few strict rules.

1JSON syntax rules
javascript
// Valid JSON — strict rules:
// - Keys MUST be in double quotes
// - Strings MUST use double quotes (no single quotes)
// - No trailing commas
// - No functions, undefined, or comments

const jsonString = '{"name":"Alice","age":30,"isAdmin":false,"scores":[95,87,92],"address":{"city":"KL"}}';

// Parse JSON string → JS object
const obj = JSON.parse(jsonString);
console.log(obj.name);           // Alice
console.log(obj.address.city);   // KL
console.log(obj.scores[0]);      // 95

// Convert JS object → JSON string
const person = { name: 'Bob', age: 25, hobbies: ['coding', 'music'] };
const str = JSON.stringify(person);
console.log(str);
// {"name":"Bob","age":25,"hobbies":["coding","music"]}

// Pretty-print with indentation
console.log(JSON.stringify(person, null, 2));
2Reading & writing JSON in Node.js
javascript
// In Node.js — reading a JSON file (data.json)
const fs = require('fs');

// READ: load file → parse → use as object
const raw  = fs.readFileSync('data.json', 'utf8');
const data = JSON.parse(raw);
console.log(data.users[0].name);

// WRITE: modify object → stringify → save file
data.users.push({ name: 'Charlie', age: 28 });
fs.writeFileSync('data.json', JSON.stringify(data, null, 2));
console.log('Saved!');

// data.json looks like:
// {
//   "users": [

1Controlled inputs

function LoginForm() {
  const [form, setForm] = useState({ email: '', password: '' });
  const [errors, setErrors] = useState({});

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
    // Clear error when user types
    if (errors[name]) setErrors(prev => ({ ...prev, [name]: '' }));
  };

  const validate = () => {
    const errs = {};
    if (!form.email.includes('@')) errs.email = 'Invalid email';
    if (form.password.length < 8)  errs.password = 'Min 8 characters';
    return errs;
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    const errs = validate();
    if (Object.keys(errs).length) { setErrors(errs); return; }
    console.log('Submitting:', form);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email"    value={form.email}    onChange={handleChange} />
      {errors.email && <span>{errors.email}</span>}
      <input name="password" value={form.password} onChange={handleChange} type="password" />
      {errors.password && <span>{errors.password}</span>}
      <button type="submit">Login</button>
    </form>
  );
}

1Custom useFetch hook

// hooks/useFetch.js — reusable data fetching
function useFetch(url) {
  const [data,    setData]    = useState(null);
  const [loading, setLoading] = useState(true);
  const [error,   setError]   = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);

    fetch(url, { signal: controller.signal })
      .then(res => { if (!res.ok) throw new Error(`HTTP ${res.status}`); return res.json(); })
      .then(setData)
      .catch(err => { if (err.name !== 'AbortError') setError(err.message); })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, [url]);

  return { data, loading, error };
}

// Using the hook
function Posts() {
  const { data: posts, loading, error } = useFetch('https://jsonplaceholder.typicode.com/posts');

  if (loading) return <p>Loading...</p>;
  if (error)   return <p>Error: {error}</p>;
  return <ul>{posts.slice(0,5).map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}

// Node built-in modules — no install needed
const fs = require('fs');    // CommonJS require
const path = require('path');

// --- READ FILE ---
// Synchronous (simple, blocks until done)
const text = fs.readFileSync('notes.txt', 'utf8');
console.log(text);

// Asynchronous (doesn't block — uses callback)
fs.readFile('notes.txt', 'utf8', (err, data) => {
  if (err) { console.error(err); return; }
  console.log(data);
});

// --- WRITE FILE ---
fs.writeFileSync('output.txt', 'Hello, file!');

// Append to file (don't overwrite)
fs.appendFileSync('log.txt', `Log: ${new Date().toISOString()}\n`);

// --- PATH utilities ---
const filePath = path.join(__dirname, 'data', 'users.json');
console.log(filePath); // absolute path, works on Windows + Mac

4Simple HTTP server
javascript
// server.js — run with: node server.js
// Then open: http://localhost:3000
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });

  if (req.url === '/') {
    res.end('Hello World!');
  } else if (req.url === '/about') {
    res.end('About page');
  } else {
    res.writeHead(404);
    res.end('Not found');
  }
});

server.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});
💡 Real world: You'd use a framework like Express instead of raw http. But understanding the raw server shows you what frameworks build on top of.

2Testing React components
javascript
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import Button from './Button';

describe('Button', () => {
  it('renders with label', () => {
    render(<Button label="Save" onClick={() => {}} />);
    expect(screen.getByText('Save')).toBeInTheDocument();
  });

  it('calls onClick when clicked', async () => {
    const handleClick = vi.fn(); // mock function
    render(<Button label="Save" onClick={handleClick} />);
    await userEvent.click(screen.getByText('Save'));
    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  it('does not call onClick when disabled', async () => {
    const handleClick = vi.fn();
    render(<Button label="Save" onClick={handleClick} disabled />);
    await userEvent.click(screen.getByText('Save'));
    expect(handleClick).not.toHaveBeenCalled();
  });
});
💡 Rule: Test behavior, not implementation. Ask "what does the user see/do?" not "what does the code do internally?"

Accessibility (a11y)

Build apps that everyone can use — including people using screen readers, keyboards only, or low-vision aids.

1Semantic HTML first
jsx
// BAD — generic divs for everything
<div onClick={submit}>Submit</div>
<div class="nav"><div>Home</div><div>About</div></div>

// GOOD — semantic elements (screen readers understand these)
<button onClick={submit}>Submit</button>
<nav><a href="/">Home</a><a href="/about">About</a></nav>

// Use the right element for the job:
// <button>  — actions / clicks
// <a href>  — navigation
// <input>   — form fields
// <label>   — label for inputs
// <main> <header> <nav> <footer> <aside> — page structure
// <h1>-<h6> — headings (only one h1 per page!)
2ARIA & keyboard accessibility
jsx
// ARIA — when semantic HTML isn't enough
<button aria-label="Close modal" onClick={close}>✕</button>
<div role="alert">Error: Invalid email</div>
<div role="status" aria-live="polite">Loading...</div>

// Always label form inputs
<label htmlFor="email">Email</label>
<input id="email" type="email" />

// Images — always alt text
<img src="avatar.jpg" alt="User profile photo" />
<img src="decorative.svg" alt="" /> {/* decorative = empty alt */}

// Keyboard: ensure all interactive elements are reachable
// Never use tabIndex > 0 (breaks natural tab order)
// Modals should trap focus inside when open
// Press Escape should close modals and dropdowns
3Accessibility checklist
javascript
// Quick checklist — run through these before shipping:

// 1. Keyboard navigation — tab through page, can you reach everything?
// 2. Color contrast — text contrast ratio >= 4.5:1 (use browser DevTools)
// 3. Images have alt text (descriptive, or empty for decorative)
// 4. Form inputs have labels
// 5. Error messages are announced (aria-live or role="alert")
// 6. Focus visible — can you SEE where focus is?
// 7. No content only communicated by color alone

// Automated check with axe (catches ~30% of issues automatically)
// npm install -D axe-core @axe-core/react
import React from 'react';
if (process.env.NODE_ENV === 'development') {
  const axe = require('@axe-core/react');
  axe(React, ReactDOM, 1000);

AI Best Practices

Use AI coding assistants to move faster — but stay in control. Understanding beats copy-pasting.

1When to use AI
javascript
// ✅ GOOD uses of AI:
// - "Explain what this code does"
// - "What's wrong with this error message: [paste error]"
// - "Suggest a better way to structure this function"
// - "Write a test for this function" (then READ and understand it)
// - "Convert this to TypeScript"
// - "Refactor this for readability"

// ❌ BAD uses of AI:
// - Copying code you don't understand into production
// - Using AI to avoid learning fundamentals
// - Trusting AI output without reviewing it
// - Sharing secrets/API keys in your prompts
// - Using AI for security-critical logic without review

// The test: can you EXPLAIN every line of AI-generated code?
// If not, you don't own it — and you can't debug it.
2Effective prompting
javascript
// Vague prompt (bad results):
"Write a login function"

// Specific prompt (good results):
`Write a React login form component that:
- Has email and password fields (controlled inputs)
- Validates email format and min 8-char password
- Shows inline error messages
- Calls onSubmit(email, password) prop on success
- Uses TypeScript with proper prop types
- No external form libraries`

// Ask for explanation alongside code:
"Write X and explain each part so I understand it"

// Ask it to review YOUR code:
"Review this code for bugs, edge cases, and improvements: [code]"

// Use AI to learn, not just to ship:
"I wrote this solution. Is there a cleaner way? What patterns am I missing?"
3Code review mindset
javascript
// When AI gives you code, ask yourself:

// 1. Do I understand what every line does?
// 2. Are there any security risks? (SQL injection, XSS, exposed keys)
// 3. Does it handle edge cases? (null, empty array, network failure)
// 4. Is it tested? Can I write a test for it?
// 5. Is it readable? Would a teammate understand this?

// Red flags in AI code:
// - eval() with user input (security risk)
// - Missing error handling
// - Hardcoded values that should be config
// - Overly complex solutions for simple problems
// - Dependencies you don't need

// Golden rule: YOU are responsible for the code you ship.
// AI is a tool, not a co-author. Review everything.
